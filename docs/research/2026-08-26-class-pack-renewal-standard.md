# Class-pack renewal / rollover: what the industry actually does

Research date 2026-08-26. Sources are gym/studio booking-software **help-center docs** (vendor-sourced,
tagged **[VENDOR]**) unless noted otherwise. Marketing pages, third-party blogs, and reviews are tagged
**[SECONDARY]** — lower confidence, included only where no primary doc surfaced. No ruling is made here;
the owner rules.

---

## Q1 — What happens to UNUSED credits when the member buys the next pack before expiry?

| Platform | Behavior | Source |
|---|---|---|
| Mindbody | Per-business config. Pricing options can be set to **never expire** ("remain available indefinitely") or tied to a contract schedule; one documented contract schedule is **"when pricing options run out"**, and support explicitly documents selling a **new contract timed to start on the date the client's existing class pass expires** — a manual queue/back-to-back pattern, not automatic stacking. [VENDOR] [How to add and set up a contract](https://support.mindbodyonline.com/s/article/203253843-Setting-up-contracts), [How to sell a contract to begin on the date that my client's class pass expires](https://support.mindbodyonline.com/s/article/211911848-How-can-I-sell-a-contract-to-begin-on-the-date-that-my-client-s-class-pass-expires) |
| ClassPass (Mindbody-owned, subscription-credit model, not classic punch card) | **Configurable rollover, capped.** Unused *purchased* credits roll over up to the credit count of the next cycle's plan (min. 10 if next plan < 10 credits). Trial/non-purchased credits never roll over. All remaining credits (rolled + purchased) are **forfeited at the end of the billing cycle** — i.e., rollover is one-cycle-deep only, not indefinite stacking. [VENDOR] [Do my credits roll over?](https://help.classpass.com/hc/en-us/articles/209367426-Do-my-credits-roll-over) |
| Glofox / ABC Glofox | A client **can hold multiple active credit packs at once**; the system draws down whichever pack is due to expire soonest first (see Q3). No explicit statement on forfeiting old credits when a new pack is bought — old pack simply keeps counting down alongside the new one until it expires. [VENDOR] [How to Set up a Service Credit Pack](https://support.glofox.com/hc/en-us/articles/213320905-How-to-Set-up-a-Service-Credit-Pack) |
| TeamUp | No primary doc found (see gap list). |
| Momence | **Default = forfeit.** Explicit quote: *"in the event that a customer doesn't use all of the pack's credits for the current renewal cycle, the remaining credits will not roll over to the next month."* Rollover is an opt-in setting (`general setup > rollover credits validity`) that a business must turn on and choose how many renewal intervals rolled credits stay valid for. Switching plans via "Transfer Subscription" (vs. cancel+rebuy) preserves rollover credits. [VENDOR] [Usage Limits, Rollover Credits & Overbooking](https://help.momence.com/en/articles/12030278-usage-limits-rollover-credits-overbooking-subscriptions), [Renewal & Freeze FAQ's](https://help.momence.com/en/articles/12030267-renewal-freeze-faq-s-subscriptions) |
| Punchpass | **Configurable, opt-in.** Studio chooses whether unused credits roll to the new pass; if enabled, studio also sets whether rolled credits **never expire or expire after 1/2/3 cycles**. The new pass gets a visible note stating how many credits rolled from the old one. [VENDOR] [Examples of passes and their settings](https://support.punchpass.com/en/articles/9462227-examples-of-passes-and-their-settings) |
| WellnessLiving | No explicit rollover-on-renewal statement found. Doc warns that if you want an included pass/membership to auto-renew *without* double-billing, you must set the package's "After Expiration" to **"Auto-renew and cancel current package contents"** — implying the un-configured default risks the old and new package contents coexisting (stacking) rather than being replaced. [VENDOR] [Packages](https://help.wellnessliving.com/en/articles/8976630-packages) |
| Arketa | Class packs have a configurable expiration window at setup; no rollover/stacking statement found. [VENDOR] [Overview: How to add pricing options](https://help.sutrapro.com/en/articles/8222461-overview-how-to-add-pricing-options) |
| Mariana Tek | Credit packages **activate immediately on purchase** and expire on their own independent clock; the "Outstanding Credits" and "Credit Expiration Details" reports exist specifically to track **multiple concurrent packages per client**, implying packages are not merged/stacked into one balance — each keeps its own expiry. No explicit statement of what happens to an old package's leftover credits when a new one is bought (they simply continue running in parallel). [VENDOR] [When does a credit package activate and expire?](https://support.marianatek.com/en/articles/2534173-when-does-a-credit-package-activate-and-expire), [Managing Customer Credit Packages](https://support.marianatek.com/en/articles/7792217-managing-customer-credit-packages) |
| Gymdesk | "Session Rollover" carries unused sessions from one billing **period to the next period of the same membership** (not framed as "buying a separate new pack"), with a configurable **rollover cap** and **rollover expiration**. [VENDOR] [Setting Up Memberships](https://docs.gymdesk.com/en/help/docs/membership-options) |
| Zen Planner | No primary rollover doc found (see gap list). |
| Wodify | Has a distinct **"Rollover Membership"** plan type: unused classes accrue up to a studio-configured max ("adds value to limited memberships by allowing clients some extra flexibility"). Dedicated article exists but returned 403 on fetch; behavior taken from search-indexed snippet, so treat as lower-confidence-vendor. [VENDOR, unconfirmed detail] [Explore Rollover Memberships](https://help.wodify.com/hc/en-us/articles/33053486593431-Explore-Rollover-Memberships) |
| PushPress | **No automatic rollover.** Doc states unused credits are handled "manually or with a separate add-on package" if rollover is desired — i.e., forfeit is the default, rollover is a manual workaround, not a system feature. [VENDOR] [Creating Appointment Types & Packages](https://help.pushpress.com/en/articles/6310720-creating-appointment-types-packages-in-pushpress-core) |
| bsport | All pack/drop-in/bundle credits carry an expiry date. Extension past expiry is a **manual, paid** studio action (e.g. £15/week past expiry) — framed as an exception a staff member grants, not automatic rollover. [VENDOR] [Extend the validity of a pass for a member](https://intercom.help/bsport-helpcenter/en/articles/4592119-extend-the-validity-of-a-pass-for-a-member) |
| Eversports Manager | "Collect unused participations" toggle: studio decides whether unused credits roll to the next period and, if so, they **stay valid through the end of the membership's overall validity** (not just one more cycle). Configurable, default not stated. [VENDOR] [Creating Memberships with Recurring Payments](https://helpcenter.eversportsmanager.com/basic-information-1) |
| Fitco (LatAm/MX) | Only marketing pages surfaced (no help-center rollover article found). Product markets "sesiones restantes" (remaining sessions) tracking and auto-reminders for vencimiento (expiry), and subscription plans **auto-renew for an equal period** at term end. [SECONDARY] [Fitco](https://www.fitcolatam.com/), [Software de cobro de membresías](https://www.fitcolatam.com/software-cobro-membresias-gimnasios-estudios-fitness-mexico/) |
| Trainingym (LatAm/ES) | Help-center confirms a **credit ("bonos") system** with configurable caducidad (expiry, in days from purchase), but the FAQ index has no rollover/stacking article. [VENDOR, partial] [Preguntas frecuentes](https://help.trainingym.com/es/knowledge/preguntas-frecuentes) |
| Fitpass MX | Not a classic class-pack; it's a monthly visit-cap subscription (e.g. "10 PACK" = 10 visits/month). Terms state the plan is **non-cumulative** and renews monthly on the purchase-anniversary date — consistent with forfeit-at-cycle-end, no stacking. [VENDOR] [FAQ](https://www.fitpass.mx/faq), [Membresías y planes](https://www.fitpass.com/mx/membresias-y-planes) |

## Q2 — Expiry norms: validity windows, does expiry extend on renewal, grace periods

| Platform | Behavior | Source |
|---|---|---|
| Mindbody | Fully configurable per pricing option: activate on sale date or on first-visit date, duration of business's choosing, or "does not expire." No universal default window. [VENDOR] [Setting up contracts](https://support.mindbodyonline.com/s/article/203253843-Setting-up-contracts) |
| ClassPass | Cycle = monthly billing period; unused non-rolled credits expire 11:59pm the day before renewal; rolled credits expire at the end of the *next* cycle (i.e., effectively ~30–60 days, capped by rollover rules above). [VENDOR] [Do my credits roll over?](https://help.classpass.com/hc/en-us/articles/209367426-Do-my-credits-roll-over) |
| Mariana Tek | Expiry is exact-timestamp based on purchase time + configured duration (e.g., "expire in 3 days" = 72 hours after purchase, to the minute). A booking made before the credit expires is honored even if the class date is after expiry. [VENDOR] [When does a credit package activate and expire?](https://support.marianatek.com/en/articles/2534173-when-does-a-credit-package-activate-and-expire), [Can a credit be used to book a class beyond the expiration date?](https://support.marianatek.com/en/articles/1987469-can-a-credit-be-used-to-book-a-class-beyond-the-expiration-date) |
| WellnessLiving | If a pass expires before the scheduled class date, the client **cannot** book with it even with unused visits remaining — expiry is a hard wall, not extended by remaining balance. [VENDOR] [Packages](https://help.wellnessliving.com/en/articles/8976630-packages) |
| Punchpass | No universal default; studio picks the expiration model (fixed date, date-of-assignment-relative, or date-of-first-use-relative). [VENDOR] [Creating a Pass](https://support.punchpass.com/en/articles/8688318-creating-a-pass) |
| bsport | Expiry is enforced but extendable manually for a fee — i.e., expiry does not extend automatically on renewal; it's a paid grace exception. [VENDOR] [Extend the validity of a pass for a member](https://intercom.help/bsport-helpcenter/en/articles/4592119-extend-the-validity-of-a-pass-for-a-member) |
| Fitpass MX | Fixed monthly cycle anchored to purchase date (e.g. purchased June 10 → renews July 10); no stated grace period; cancellation requires 48h notice before next cycle. [VENDOR] [FAQ](https://www.fitpass.mx/faq) |
| Trainingym | Caducidad (expiry) is a configurable day-count from bono purchase/assignment; no universal default or grace period documented. [VENDOR] [Preguntas frecuentes](https://help.trainingym.com/es/knowledge/preguntas-frecuentes) |

**Convergent pattern:** none of the vendors document expiry "extending" automatically on renewal. Every platform that addresses it treats validity window as fixed at pack-creation time (studio-configured), with expired-but-unused credit either hard-forfeited (WellnessLiving, Mariana Tek, Fitpass-style) or paid-extendable as a manual exception (bsport).

## Q3 — Can a member hold two active packs? Which pack does a booking draw from?

| Platform | Behavior | Source |
|---|---|---|
| Glofox / ABC Glofox | **Yes, explicitly.** *"The system looks for which active, relevant credit will expire first... if your client has multiple credit packs, the system will take the credit due to expire soonest."* A pack with a set expiry date is drawn before a non-expiring pack. This is the **only platform with an explicit, documented consumption-order rule** found in this research: **soonest-expiry-first (FIFO by expiry), not FIFO/LIFO by purchase date.** [VENDOR] [How to Set up a Service Credit Pack](https://support.glofox.com/hc/en-us/articles/213320905-How-to-Set-up-a-Service-Credit-Pack) |
| Mariana Tek | Implicitly yes — per-client multi-package tracking exists via the "Outstanding Credits" report, and each package has its own independent expiry clock, but no article states which package a booking draws from first. [VENDOR, gap] [Managing Customer Credit Packages](https://support.marianatek.com/en/articles/7792217-managing-customer-credit-packages) |
| WellnessLiving, PushPress, Punchpass, Mindbody, Momence, Gymdesk, Arketa, bsport, Eversports | No primary doc found stating whether two packs can be simultaneously active or, if so, draw order. Treat as an open gap per platform, not as "no" — most support multiple purchase-option types on one client record, but the priority rule when 2+ of the *same type* are active is undocumented. |

## Q4 — Post-mortems / member-confusion complaints about credit balances

| Source | Finding | Type |
|---|---|---|
| Blackburn v. ClassPass USA LLC; Chabolla v. ClassPass Inc. (class-action complaints) | Allege ClassPass's rollover-then-forfeit design (partial rollover, then hard expiry) functions like an unlawfully-expiring gift certificate under California law, and that credits are lost entirely on cancellation with **no cash-out or transfer mechanism**. This is the clearest documented "post-mortem" of a credit-balance design generating real (legal, not just support-ticket) blowback. [SECONDARY — legal filings, not a vendor doc] [ClassPass Class Action Challenges Platform's 30-Day Credit Expiration Policy](https://www.classaction.org/news/classpass-class-action-challenges-platforms-30-day-credit-expiration-policy) |
| Search-aggregated Reddit sentiment (could not access reddit.com directly — blocked from this tool's crawler; findings are from a secondary summary, not the primary threads) | Users reportedly call ClassPass credit expiry "a scam"/"unethical," citing that **credits paid for expire and are only usable while continuing to pay** — i.e., the complaint is specifically that a balance the member believes they "own" evaporates on cancel/lapse, a display/expectation mismatch rather than a bug. [SECONDARY, unverified primary] |
| Capterra Mindbody reviews (pages 17/27/31) | General software-reliability complaints (slowness, bugs, payment failures, inconsistent support) — not specifically about credit-balance confusion, but corroborates that balance-adjacent transactional failures (a payment not registering against the right pass/cycle) are a recurring review theme. [SECONDARY] [Mindbody Reviews — Capterra](https://www.capterra.com/p/40229/MINDBODY/reviews/) |

**What generates tickets, per the above:** (a) a balance that silently disappears at a boundary the member didn't track (cycle-end forfeiture — ClassPass's core complaint), and (b) no cash/transfer path when a balance is stranded by cancellation. Both are about the *display and irreversibility* of a forfeiture event, not about which stacking algorithm is used.

## What the sources converge on (no ruling — attributed only)

Ranked by how many independent vendor docs support the pattern, for a **small class-only gym**:

1. **Rollover/stacking is treated as a per-gym configurable toggle, not a hardwired platform behavior**, across every vendor that documents it at all (Momence, Punchpass, Gymdesk, Eversports, Wodify, Mindbody, WellnessLiving). None of them ship one universal forced rule.
2. **Where a documented default exists, it is forfeit-on-renewal, not stack-on-renewal.** Momence's doc states this explicitly ("remaining credits will not roll over... unless configured"); PushPress's doc frames rollover as a manual workaround, implying no rollover is the default; ClassPass caps rollover at one cycle and hard-forfeits after. Nobody's documented *default* is unlimited/indefinite stacking.
3. **Vigencia (expiry) is not extended by renewal anywhere found.** Every platform that addresses this treats the validity window as fixed at pack-creation and enforces it as a hard wall (WellnessLiving, Mariana Tek), with extension only as a manual, sometimes-paid staff override (bsport).
4. **Holding two simultaneous active packs is explicitly supported by at least one major vendor (Glofox), and its only documented consumption-order rule anywhere in this research is soonest-expiry-first** — i.e., if a design needs a tie-break rule between packs, "drain the one expiring soonest" is the one primary source that names an algorithm.
5. **Member-facing risk is concentrated at the forfeiture/cancellation boundary**, not at the stacking rule itself — the one real post-mortem found (ClassPass litigation) is about credits vanishing without visibility or recourse, which argues for whatever rule is chosen to be paired with clear balance/expiry display, regardless of which stacking/rollover behavior is picked.
