## The core insight

**The member picker already exists.** `AGREGAR WALK-IN` in the Agenda class sheet
already opens a search over every `cliente` in the gym. This is not a missing surface —
it is a missing *second write path* behind the surface that is already there.

Today that tap writes `status='asistida'`: present now, class consumed, visit stamped
to the ledger. For a member phoning about tomorrow's 06:00 that is a false record. What
is missing is the ability to write `status='reservada'` instead.

Anyone who starts this ticket by building a booking modal has misread it.

## Owner rulings — do not re-litigate

Decided 2026-08-03. All four were live product questions; all four are closed.

1. **Charge at booking**, on both paths. Not check-in settlement. (See #233 below.)
2. **Zero balance / expired plan → block**, with the same errors the member path
   raises. No staff override, no negative balance, no warn-and-proceed.
3. **One button, tense-derived.** Not two buttons with a mode to choose.
4. **Copy:** `AGREGAR VISITA` / chip `SIN RESERVA`. The `is_walk_in` identifier stays
   English everywhere in the database and types — operators never see it.

## Read the amendment comment before the spec body

The [amendment comment on #235](https://github.com/Vack99/RED-2.0/issues/235#issuecomment-5173841297)
corrects the body and is load-bearing.

The body has the tense predicate computed at render time. That inherits #231's
frozen-clock defect: a class sheet left open across the arrival window's opening edge
would still read `AGREGAR RESERVA`, and the tap would create a future booking for a
class whose window is already open — the exact false record the spec exists to prevent.

**Evaluate the predicate inside the tap handler, against a clock read at that instant.**
A stale label is cosmetic. A stale write is a false record.
